# md-slot-finisher

도구가 md 안에 만들어 둔 **칸 안**과 **YAML 빈 항목**만 채우는 스킬임.
무엇을 할지, 끝났는지는 전부 도구 명령(`run.py`)의 결과로만 판단함. 기억·추측으로 판단하지 않음.

## 칸의 종류

| 칸 | 모양 | 할 일 |
|---|---|---|
| 번역 칸 | `<!-- TR P00012 h=3fa9c1d2e4b5 -->` / `> (번역 필요)` / `<!-- /TR -->` | `> (번역 필요)` 줄만 번역문으로 바꿈 |
| 요약 칸 (논문만) | `<!-- SUM -->` / `> (요약 필요)` / `<!-- /SUM -->` | `> (요약 필요)` 줄만 요약으로 바꿈 |
| 기존 정리본 칸 | `<!-- LEGACY -->` … `<!-- /LEGACY -->` | `--todo` 가 요청할 때만 다듬음 (내용 추가·삭제 금지) |
| 서지 빈 항목 (논문만) | md 맨 위 YAML 의 값이 빈 항목 | `--todo` 가 알려 준 항목만 채움 |

## 명령 (도구 폴더에서 실행)

| 명령 | 하는 일 | 종료 코드 |
|---|---|---|
| `python run.py --todo [문서] [--limit N]` | 다음 칸 목록 (읽기만) | 0 = 남은 칸 없음 / 1 = 할 일 있음 / 2 = 문서를 찾을 수 없음 |
| `python run.py --check [문서]` | 채운 칸 검사 (읽기만) | 0 = 통과 / 1 = 문제 있음 |
| `python run.py --apply` | 반영·인덱스 갱신 | 출력 메시지를 그대로 보고 |

- `문서` = doc_id(예 `D335259a3`) 또는 md 파일명 일부.
- 종료 코드 확인법: PowerShell `echo $LASTEXITCODE` / cmd `echo %ERRORLEVEL%` / bash `echo $?` (명령 바로 다음에 실행).
- Windows 에서 `python` 을 찾을 수 없다고 나오면 `py` 로 한 번만 다시 시도함.

## 고정 절차 (이 순서 그대로)

| 단계 | 입력 | 할 일 | 다음 단계로 가는 조건 |
|---|---|---|---|
| 0. 도구 찾기 | 사용자가 준 경로 | 그 경로, 그 바로 아래 폴더들, 상위 폴더들(과 각각의 바로 아래 폴더) 중에서 `AI_INSTRUCTIONS.md` + `run.py` + `pdf2md/` 가 **셋 다 같이 있는** 폴더를 찾음. 폴더 이름으로 판단하지 않음 | 찾음 → 1 / 못 찾음 → "먼저 도구 폴더의 RUN.bat 을 실행해 md 를 만들어야 함" 안내 후 **끝** |
| 1. 규칙 읽기 | 도구 폴더 | `AI_INSTRUCTIONS.md` 전체, `_glossary.md` 전체를 읽음 | 둘 다 읽음 → 2 |
| 2. 명령 확인 | 도구 폴더 | `python run.py --todo --limit 1` 실행 | 종료 코드 0 또는 1 → 3 / 명령 자체가 실행 안 됨(셸 없음, python 없음, 오류로 중단) → "명령 없는 모드"(아래)로 3부터 진행 |
| 3. 범위 정하기 | 사용자 요청, `_ai_queue/STATUS.md` 첫 줄 | 남은 문서 수·빈 칸 수를 한 번 보고함. 사용자가 범위를 안 정했으면 "문서 1개를 완전히 끝낼 때까지". "전부"면 STATUS 순서대로 계속. 대상 문서는 **매번 `--todo` 결과로** 정함 (이전 대화의 목록 사용 금지) | 대상 문서 1개 정함 → 4 / `--todo` 종료 코드 0 (남은 문서 없음) → 8 |
| 4. 번역 반복 | `--todo <문서> --limit 20` 결과 | 각 번역 칸의 `> (번역 필요)` 줄만 번역문으로 바꿈(여러 줄이면 줄마다 앞에 `> `). 20칸 쓰면 바로 저장. 새 전문 용어는 `_glossary.md` 맨 아래에 한 줄 추가. 그다음 `--check <문서>` → 지적된 칸만 고침 | `--todo <문서>` 에 번역 칸 0개 → 5 / 번역 칸 남음 → 4 반복 / `--todo <문서>` 종료 코드 2 → 그 문서 건너뜀 → 3 |
| 5. 요약 (논문만) | `--todo <문서>` 가 준 섹션별 줄 범위 | 그 줄 범위의 **번역문**을 섹션별로 읽고 요약 칸을 `AI_INSTRUCTIONS.md` §4 꼭지형식으로 씀. 책이면 쓰지 않음 | 요약 칸 없음 또는 다 씀 → 6 |
| 6. 서지 (논문만) | `--todo <문서>` 가 알려 준 YAML 빈 항목 | 그 항목만 원문 첫 쪽 내용으로 채움. 확인할 수 없으면 비워 둠 | 다 씀 → 7 |
| 7. 완료 확인 | 문서 | `--todo <문서>` 와 `--check <문서>` 실행 | 둘 다 종료 코드 0 → `--apply` 실행 → 8 / 하나라도 0 아님 → 4 |
| 8. 보고 | 결과 | `references/report-template.md` 양식으로 보고 (한국어, `-` 꼭지, 음슴체) | 범위가 남음 → 3 / 범위 끝 → **끝** |

### 명령 없는 모드 (2단계에서 명령이 실행 안 될 때)
- `_ai_queue/STATUS.md` 맨 위 문서의 md 를 대상으로 함 (md 파일이 없으면 그 문서는 건너뜀).
- md 에서 `(번역 필요)` 를 검색해 나온 칸을 위에서부터 20개씩 4단계와 같은 규칙으로 채움. 검색 결과 0개가 될 때까지 반복.
- 논문이면 `(요약 필요)` 를 검색해 5단계, YAML 의 빈 서지 항목으로 6단계를 진행함 (섹션 범위는 md 의 `##` 제목으로 나눔).
- 검사·반영은 할 수 없음 → 보고의 "검사"를 `미실행 (RUN.bat 실행 필요)` 로 적고 사용자에게 RUN.bat 실행을 안내함.

## 번역할 때 (세부 규칙은 `AI_INSTRUCTIONS.md` 가 우선)
- 한 글자·한 문단도 빼지 않음. 요약·생략·합치기·나누기 금지. 원문이 깨진 OCR·안내문이어도 그대로 번역함.
- `_glossary.md` 에 있는 용어는 그 번역을 씀.
- 예시: `examples/tr-before-after.md`, 요약 예시: `examples/sum-example.md`, 예외 처리: `references/procedure-detail.md`.

## 파일을 고치는 방법
- md 전체를 한 번에 읽지 않음. `--todo` 가 준 줄 번호 앞뒤만 읽음.
- `> (번역 필요)` 줄은 여러 곳에 똑같이 있음. 바꿀 때는 **바로 위 표식 줄(예 `<!-- TR P00012 h=3fa9c1d2e4b5 -->`)까지 포함해서** 찾고, 표식 줄은 한 글자도 바꾸지 않고 그대로 다시 씀.

  찾을 글:
  ```
  <!-- TR P00012 h=3fa9c1d2e4b5 -->
  > (번역 필요)
  ```
  바꿀 글:
  ```
  <!-- TR P00012 h=3fa9c1d2e4b5 -->
  > 번역문 첫 줄
  > 번역문 둘째 줄
  ```

## 절대 규칙
| 금지 | 예 |
|---|---|
| 표식 줄(`<!-- … -->`)을 고치거나 지움 | `<!-- /TR -->` 삭제, `P00012` → `P12` 변경 모두 금지 |
| 칸 밖(원문·제목·그림 링크)을 고침 | 원문 오타 수정 금지. 고쳐도 다음 실행 때 사라짐 |
| 이미 채워진 칸을 다시 씀 | `--check` 가 지적한 칸만 고침 |
| 도구 파일을 씀 | `_figures/*`, json, `STATUS.md`, `QA_report.md`, YAML 의 `doc_id`·`source_pdf`·`status_*` 쓰기 금지 |
| `_glossary.md` 기존 줄 변경 | 맨 아래 줄 추가만 허용 |
| `_to_delete/` 접근 | 읽지도 쓰지도 않음. 삭제된 문서를 되살리거나 md 를 새로 만들지 않음 |
| 번역을 요약·생략 | "이 단락은 실험 장치를 설명함" 같은 요약 금지 |
| 책 요약 | 책은 요약 칸을 쓰지 않음 |
| 기억·추측으로 "다 했다" 판단 | 완료는 `--todo <문서>` = 0 그리고 `--check <문서>` = 0 일 때만 |

## 출력 한도·세션 끊김
- 한 번에 20칸까지만 쓰고 바로 저장함.
- 중간에 끊겨도 괜찮음. 다음 실행 때 3단계부터 `--todo` 로 이어서 하면 됨.
