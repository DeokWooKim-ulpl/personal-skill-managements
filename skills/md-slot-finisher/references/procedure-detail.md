# 예외 처리

절차 중 아래 상황이 생기면 이 표대로 처리함. 표에 없는 상황은 해당 칸을 건드리지 말고 보고에 그대로 적음.

## 1. 표식·파일

| 상황 | 처리 |
|---|---|
| 표식 줄이 깨짐 (글자 빠짐, `-->` 없음, 줄이 합쳐짐) | 원래 모양으로 복구: `<!-- TR P00012 h=3fa9c1d2e4b5 -->` / `<!-- /TR -->`, `<!-- SUM -->` / `<!-- /SUM -->`, `<!-- LEGACY -->` / `<!-- /LEGACY -->`. 표식은 각각 한 줄을 차지함 |
| 깨진 표식의 번호(`P…`)나 `h=` 값을 알 수 없음 | 추측해서 만들지 않음. 그 칸은 그대로 두고 보고에 "표식 복구 불가: 줄 N" 으로 적음 |
| 칸 밖을 실수로 고침 | 바꾸기 전 내용을 알면 되돌림. 모르면 그 문서 작업을 멈추고 보고함 (사용자가 RUN.bat 을 실행하면 도구가 칸 내용을 거둬 저장한 뒤 md 를 다시 만듦) |
| `--todo <문서>` 종료 코드 2 | 문서가 삭제됐거나 이름이 모호함. md 파일명 일부로 지정했으면 doc_id 로 한 번 다시 지정. 그래도 2 면 건너뛰고 절차 3단계로 가서 다음 문서를 받음 |
| md 파일이 사라짐 (명령 없는 모드) | 그 문서 건너뜀. 새로 만들지 않음 |
| 다른 PC 가 감시 중이라는 `--apply` 메시지 | 정상임. `--apply` 가 그쪽에 맡기고 끝냄. 기다리지 않고 보고로 넘어감 |
| `python` 실행 불가 | `py` 로 1회 재시도. 그래도 안 되면 명령 없는 모드 |

## 2. `--check` 가 지적한 문제

실제 메시지 문구는 `run.py` 가 정함. 아래는 문제 **유형**별 대응임. 메시지가 가리키는 칸(줄 번호·`P…` 번호)만 고침.

| 문제 유형 | 고치는 법 |
|---|---|
| 칸이 아직 비어 있음 (`(번역 필요)`·`(요약 필요)` 남음) | 그 칸을 채움 |
| 표식 손상·짝이 맞지 않음 | 1절 첫 줄대로 복구 |
| 칸 안 줄 앞에 `> ` 없음 | 칸 안 모든 줄 앞에 `> ` 붙임 (빈 줄도 `>` 로) |
| 칸 밖이 바뀜 | 1절 "칸 밖을 실수로 고침" 대로 |
| 번역 누락 의심 (분량 부족, 문장 빠짐, 영어 문장 남음) | 원문 단락을 다시 읽고 빠진 문장을 모두 넣어 그 칸을 다시 씀 |
| 수식·기호 문제 | `AI_INSTRUCTIONS.md` 의 수식 규칙대로 원문 기호를 그대로 옮김 (예 `$\omega_0$는`, 구분자 안쪽 공백 없음) |
| 용어가 `_glossary.md` 와 다름 | 용어집의 번역으로 바꿈 |
| LEGACY 칸의 내용이 바뀜 | 다듬기 전 문장의 뜻으로 되돌림. 추가·삭제한 문장을 원래대로 |
| 고칠 방법을 알 수 없는 메시지 | 그 칸을 건드리지 않음. 보고의 "검사"에 `문제 N (메시지 원문 그대로)` 로 적음 |

## 3. 원문 내용

| 원문 | 처리 |
|---|---|
| 한국어 | 번역하지 않고 그대로 옮김 |
| 영어 외 언어 (독일어·일본어 등) | 한국어로 번역 |
| 수식만 있는 단락 | 수식을 그대로 옮김 (번역할 글이 없어도 칸은 채움) |
| 깨진 OCR·저작권 안내문·쪽 머리글 | 읽히는 만큼 그대로 번역. 빼지 않음 |
| 일부 또는 전부 판독 불가 | 읽히는 부분은 번역하고 읽을 수 없는 부분은 `[판독 불가]` 로 적음 |
| 참고문헌 목록 단락 | `AI_INSTRUCTIONS.md` 의 규칙을 따름 |
